# Image Background Remover 第一阶段需求文档

- 文档状态：Draft v1
- 日期：2026-07-14
- 阶段：需求验证 MVP
- 目标市场：全球英文用户，优先小型电商卖家
- 部署平台：Cloudflare
- 背景移除服务：Remove.bg API

## 1. 产品概述

第一阶段交付一个无需注册的 Web 工具，帮助用户将单张或一批商品原图转换为透明背景或统一白底的商品图，并下载处理结果。

本阶段的目的不是建设完整 SaaS，而是验证以下假设：

1. 用户愿意上传真实商品图片，而不只是浏览落地页。
2. Remove.bg 的自动处理质量能够满足大部分普通实体商品。
3. 批量处理、统一尺寸和 ZIP 下载比单张通用抠图更有价值。
4. 用户愿意为后续批次支付至少 USD 5。

## 2. 成功标准

产品上线后的首轮验证周期为 7 天。

| 指标 | 目标 |
|---|---:|
| 真实上传用户 | 至少 10 人 |
| 完成处理的图片 | 至少 100 张 |
| 从上传到成功下载的完成率 | 不低于 70% |
| 用户主观认可的结果比例 | 不低于 85% |
| 表达后续付费意愿的用户 | 至少 3 人 |
| 可接受的试付价格 | 每批至少 USD 5 |

本阶段不以注册量、订阅收入或 SEO 流量作为成功标准。

## 3. 目标用户

### 3.1 主要用户

- 每周需要处理 20-500 张商品图的小型电商卖家。
- 使用 Shopify、Amazon、Etsy、eBay 等平台的独立卖家。
- 希望快速得到统一白底图的商品摄影师或代运营人员。

### 3.2 首版适合的图片

- 鞋服、家居用品、玩具、包装商品等轮廓清晰的实体商品。
- 主体与原背景有一定颜色或明暗对比的图片。
- JPG、PNG 或 WebP 格式的普通商品照片。

### 3.3 首版不承诺的图片

- 头发、宠物毛发、网纱等复杂细边缘。
- 透明玻璃、半透明塑料、烟雾或液体。
- 主体与背景高度相似的图片。
- 多主体、强阴影或严重遮挡的图片。

页面必须明确说明上述限制，不能使用“所有图片均可完美处理”等承诺。

## 4. 第一阶段范围

### 4.1 P0 必须交付

1. 英文产品落地页。
2. 单张图片上传和处理。
3. 最多 20 张图片的批量处理。
4. 透明背景和纯白背景两种输出。
5. Original、Amazon、Etsy、Shopify 四种尺寸选项。
6. 单张下载和批量 ZIP 下载。
7. 单张处理状态、失败原因和重试操作。
8. Cloudflare Turnstile 防滥用验证。
9. 基础隐私说明、使用限制和错误提示。
10. 不使用数据库、KV、R2、Durable Objects 或其他持久化存储。

### 4.2 P1 有余力再做

- 图片上传前的客户端压缩。
- 白色以外的纯色背景。
- 处理前后的拖动对比组件。
- 用户主动提交结果满意度。

P1 功能不能影响 P0 上线时间。

### 4.3 明确不做

- 用户注册、登录和团队账号。
- Stripe 支付、套餐和积分系统。
- 图片历史记录或再次下载。
- 云端保存原图、结果图或 ZIP 文件。
- 直接写回 Shopify、Amazon、Etsy 或其他平台。
- 生成式场景背景、阴影生成和图片美化。
- 手工擦除、恢复或画笔精修。
- 自训练或部署背景分割模型。
- 视频背景移除。
- 移动 App、桌面 App 和浏览器扩展。

## 5. 核心用户流程

### 5.1 首次访问

1. 用户打开首页。
2. 用户看到产品价值、前后对比、支持格式和隐私说明。
3. 用户点击上传区域或把图片拖入页面。
4. 页面在真正调用 API 前完成 Turnstile 验证。

### 5.2 图片处理

1. 浏览器校验文件格式、大小和数量。
2. 用户选择输出背景和尺寸预设。
3. 浏览器逐张向 Cloudflare Worker 发起请求，并限制并发数。
4. Worker 在单次请求生命周期内接收图片并转发给 Remove.bg。
5. Worker 将 Remove.bg 返回的透明 PNG 流式返回浏览器。
6. 浏览器按用户选择合成白底、调整画布和居中主体。
7. 页面展示每张图片的成功或失败状态。

### 5.3 下载

- 单张任务：用户可直接下载 PNG。
- 批量任务：用户可单独下载，也可在全部可用结果处理完后下载 ZIP。
- ZIP 在浏览器内生成，不上传到服务器。
- 用户关闭或刷新页面后，所有处理结果丢失，页面应提前提示。

## 6. 功能需求与验收标准

### FR-01 文件选择

需求：用户可以点击选择或拖放图片。

验收标准：

- 支持 `.jpg`、`.jpeg`、`.png`、`.webp`。
- 单次最多选择 20 张图片。
- 单张文件大小上限作为部署配置项，首发建议值为 10 MB。
- 文件数量、扩展名、MIME 类型或大小不符合要求时，在调用 API 前拦截。
- 错误提示必须指出具体文件和失败原因。
- 重复选择同一个文件时不重复加入列表。

### FR-02 图片列表

需求：批量任务开始前，用户可以确认待处理图片。

验收标准：

- 每张图片显示缩略图、文件名和文件大小。
- 用户可以删除单张图片或清空全部图片。
- 图片处理开始后，已发送的图片不能从任务中删除。
- 每张图片必须具有 `waiting`、`processing`、`success` 或 `failed` 状态。

### FR-03 输出设置

需求：用户可以为当前批次选择背景和尺寸。

背景选项：

- `Transparent`：透明 PNG。
- `White`：`#FFFFFF` 白色背景 PNG。

尺寸选项：

| 预设 | 输出尺寸 | 处理规则 |
|---|---:|---|
| Original | 保持 Remove.bg 输出尺寸 | 不改变画布 |
| Amazon | 2000 x 2000 px | 主体居中并保留统一留白 |
| Etsy | 2000 x 2000 px | 主体居中并保留统一留白 |
| Shopify | 2048 x 2048 px | 主体居中并保留统一留白 |

验收标准：

- 默认背景为 `White`。
- 默认尺寸为 `Original`。
- 预设处理不得拉伸主体，必须保持原始宽高比。
- 主体应完整显示在画布内，不得裁切。
- Amazon 和 Etsy 首版尺寸虽然相同，仍保留独立选项，便于后续调整规则和记录用户偏好。

### FR-04 Turnstile 验证

需求：在消耗 Remove.bg 额度前验证请求来自真实用户。

验收标准：

- 浏览器随处理请求提交 Turnstile token。
- Worker 在调用 Remove.bg 前向 Cloudflare 验证 token。
- token 缺失、失效或验证失败时，不得调用 Remove.bg。
- 页面向用户显示可理解的重试提示，不暴露内部验证详情。

### FR-05 Remove.bg 处理

需求：Cloudflare Worker 代理 Remove.bg API，API Key 只能存在于服务端环境变量中。

验收标准：

- 请求发送至 Remove.bg 官方 API。
- `REMOVE_BG_API_KEY` 使用 Cloudflare Secret 管理。
- 浏览器源代码、网络请求和错误消息中不得出现 API Key。
- Worker 校验请求方法、文件字段、文件类型和大小后才调用上游。
- Remove.bg 成功时，Worker 返回透明 PNG。
- Remove.bg 返回错误时，Worker 映射为稳定的站内错误码。
- Worker 不记录图片二进制内容。

### FR-06 批量调度

需求：批量任务由浏览器负责排队，Worker 每次只处理一张图片。

验收标准：

- 浏览器默认最多并发处理 2 张图片。
- 一张失败不能终止其余图片。
- 用户可以单独重试失败图片。
- 重试必须重新通过有效的防滥用验证。
- 页面显示 `已完成数量 / 总数量`。

说明：不能使用 Worker 内存保存跨请求队列或计数。Worker 实例并非稳定常驻，内存状态不能作为可靠限流或任务状态。

### FR-07 浏览器端成图

需求：Remove.bg 返回透明 PNG 后，由浏览器完成背景合成和尺寸预设。

验收标准：

- 透明模式保留 alpha 通道。
- 白底模式使用 `#FFFFFF` 填充。
- 尺寸预设在浏览器 Canvas 中完成。
- 输出图片不得上传回 Worker。
- 同一张透明结果切换背景或尺寸时，不得再次调用 Remove.bg。

### FR-08 结果预览

需求：用户可以在下载前查看结果。

验收标准：

- 成功结果显示处理后缩略图。
- 透明背景使用棋盘格表示。
- 每张成功图片提供单独下载按钮。
- 每张失败图片显示简短原因和重试按钮。
- 预览使用浏览器内的临时 Object URL，并在图片移除或页面卸载时释放。

### FR-09 下载

需求：用户可以下载单张图片或批量 ZIP。

验收标准：

- 输出统一为 PNG。
- 单张输出文件名为 `<原文件名>-removed.png`。
- 批量 ZIP 文件名为 `background-removed-images.zip`。
- ZIP 只包含成功图片。
- 存在失败图片时，下载按钮旁提示成功和失败数量。
- ZIP 在浏览器内生成，不经过 Worker。

### FR-10 隐私说明

需求：页面必须准确描述图片如何处理。

页面至少说明：

- 本网站不使用持久化存储保存图片。
- 图片会经 Cloudflare Worker 转发给 Remove.bg 进行处理。
- 图片在单次请求期间存在于内存或网络流中，处理完成后本网站不保留副本。
- Remove.bg 对上传数据的处理仍受其隐私政策和服务条款约束。
- 刷新或关闭页面后无法恢复结果。

不能宣称“图片从不离开设备”，因为图片会发送给 Cloudflare 和 Remove.bg。

### FR-11 基础反馈入口

需求：为了完成需求验证，用户能够表达结果是否可用和后续付费意愿。

验收标准：

- 结果区提供 `Good result` 和 `Needs improvement` 两个反馈入口。
- 页面提供一个外部反馈或联系入口，用于收集后续付费意愿。
- 第一阶段不建设反馈数据库；可链接到独立表单或邮件。
- 在用户主动提交前，不发送图片或文件名到反馈渠道。

## 7. 错误处理

前端只显示稳定、可行动的用户提示。

| 站内错误码 | 场景 | 用户提示方向 |
|---|---|---|
| `INVALID_FILE` | 格式、MIME 或文件损坏 | 选择支持的图片 |
| `FILE_TOO_LARGE` | 超出单张上限 | 压缩图片后重试 |
| `TOO_MANY_FILES` | 超过 20 张 | 减少本批图片 |
| `VERIFICATION_FAILED` | Turnstile 失败 | 重新验证后重试 |
| `UPSTREAM_REJECTED` | Remove.bg 无法处理 | 换一张主体更清晰的图片 |
| `UPSTREAM_QUOTA_EXCEEDED` | Remove.bg 额度不足 | 服务暂不可用，稍后再试 |
| `UPSTREAM_RATE_LIMITED` | Remove.bg 限流 | 稍后自动或手动重试 |
| `UPSTREAM_UNAVAILABLE` | Remove.bg 或网络异常 | 保留任务并允许重试 |
| `PROCESSING_FAILED` | 未分类错误 | 重试，仍失败则联系支持 |

服务端日志可以记录时间、错误码、上游状态码和请求耗时，但不能记录图片内容、文件名、Remove.bg API Key 或 Turnstile token。

## 8. 非功能需求

### 8.1 性能

- 首页首屏不依赖 Remove.bg API。
- 用户选择图片后立即生成本地缩略图。
- 单图处理期间持续显示明确状态，不能出现无反馈等待。
- 批量处理采用并发 2，避免浏览器和上游瞬时压力过大。
- Worker 尽可能流式返回上游图片，避免无必要的二次完整复制。

### 8.2 安全

- API Key 仅存储在 Cloudflare Secret。
- Worker 只接受预期来源、方法和内容类型。
- 配置合理的 CORS，仅允许正式站点域名和本地开发地址。
- 响应设置 `Cache-Control: no-store`。
- 不在 URL 查询参数中传递图片、token 或密钥。
- 对客户端输入做文件签名/MIME 类型和大小校验，不能只信任扩展名。

### 8.3 防滥用

- P0 使用 Turnstile。
- 边缘速率限制优先通过 Cloudflare WAF/Rate Limiting Rules 配置。
- 在不使用 KV 或 Durable Objects 的前提下，不实现应用层跨请求精确计数。
- Remove.bg 账户额度作为最终成本上限，额度告警需在控制台配置。
- 若当前 Cloudflare 套餐无法提供所需速率限制能力，先使用 Turnstile 和较低批量并发上线验证，不为此引入数据库。

### 8.4 可用性与无障碍

- 上传区域可使用键盘操作。
- 重要按钮有明确文本标签。
- 处理状态不能只用颜色表达。
- 错误信息与对应图片关联。
- 支持桌面和移动浏览器，但第一阶段以桌面 Chrome、Safari、Edge 最新稳定版为主要验收范围。

## 9. 技术架构约束

```text
Browser
  ├─ Local preview and batch queue
  ├─ Canvas: white background, resize and centering
  └─ Client-side ZIP generation
          │ one image per request
          ▼
Cloudflare Worker
  ├─ Request validation
  ├─ Turnstile verification
  ├─ Remove.bg API proxy
  └─ Stream PNG response with no-store
          │
          ▼
Remove.bg API
```

### 9.1 数据生命周期

| 数据 | 所在位置 | 生命周期 | 是否持久化 |
|---|---|---|---|
| 原始图片 | 浏览器、Worker 请求、Remove.bg | 单次处理期间 | 本网站否 |
| 透明结果图 | Worker 响应、浏览器内存 | 当前页面会话 | 否 |
| 白底/尺寸结果 | 浏览器内存 | 当前页面会话 | 否 |
| ZIP | 浏览器内存 | 生成和下载期间 | 否 |
| API Key | Cloudflare Secret | 配置生命周期 | 是，仅密钥配置 |
| 错误日志 | Cloudflare 日志 | 按平台配置 | 仅非图片元数据 |

### 9.2 必需环境变量

- `REMOVE_BG_API_KEY`
- `TURNSTILE_SECRET_KEY`
- `ALLOWED_ORIGIN`
- `MAX_FILE_SIZE_BYTES`

Turnstile Site Key 可作为前端公开配置，不属于密钥。

## 10. 页面结构

第一阶段只需要一个主页面和必要的静态法律页面。

### 10.1 首页

1. Hero：说明“批量把商品图变成干净白底图”。
2. 上传区：拖放、格式与数量提示。
3. 输出设置：背景与尺寸。
4. 图片任务列表：状态、预览、重试和下载。
5. 批量下载区：ZIP 下载及成功/失败数量。
6. 使用限制：复杂边缘和透明物体说明。
7. 隐私说明：图片会发送给 Remove.bg，但本站不保存。
8. 反馈入口：结果评价和付费意愿联系。

### 10.2 静态页面

- Privacy Policy
- Terms of Use

法律页面只描述实际行为，不加入尚未实现的账户、支付或数据保留机制。

## 11. 埋点与验证数据

在“不建设业务存储”的前提下，可以使用 Cloudflare Web Analytics 获取匿名页面级数据。

建议观察：

- 首页访问量。
- 上传区域交互次数。
- 开始处理的会话数。
- 处理成功和失败数量。
- 单张和 ZIP 下载次数。
- 反馈入口点击次数。

如果所选分析方案需要发送文件名、图片内容或可识别用户的信息，则本阶段不使用该方案。

## 12. 上线验收清单

### 功能

- [ ] 单张 JPG、PNG、WebP 可以成功处理和下载。
- [ ] 20 张混合格式图片可以排队处理。
- [ ] 单张失败不影响其他图片。
- [ ] 透明和白底输出正确。
- [ ] 四种尺寸选项不会拉伸或裁切主体。
- [ ] ZIP 只包含成功结果且文件名正确。
- [ ] 切换背景或尺寸不会重复调用 Remove.bg。

### 隐私与安全

- [ ] 浏览器中无法看到 Remove.bg API Key。
- [ ] Turnstile 失败时 Remove.bg 不产生调用。
- [ ] Worker、浏览器和 CDN 响应均不缓存用户图片。
- [ ] 没有使用 R2、KV、数据库或 Durable Objects。
- [ ] 日志中没有图片内容、文件名、密钥或验证 token。
- [ ] 隐私页面明确提到 Remove.bg 第三方处理。

### 异常

- [ ] 超大文件在上传前被拦截。
- [ ] 伪造 MIME 类型的文件被拒绝。
- [ ] Remove.bg 额度不足时显示明确提示。
- [ ] Remove.bg 超时或限流后可以单张重试。
- [ ] 页面刷新前提示未下载结果将丢失。

### 浏览器

- [ ] Chrome 最新稳定版桌面端通过。
- [ ] Edge 最新稳定版桌面端通过。
- [ ] Safari 最新稳定版桌面端通过。
- [ ] iOS Safari 和 Android Chrome 可以完成单张流程。

## 13. 开发完成定义

第一阶段只有在以下条件全部满足时才算完成：

1. 所有 P0 功能已经部署到 Cloudflare 正式环境。
2. 上线验收清单全部通过，或已记录并接受非阻塞问题。
3. Remove.bg API Key、Turnstile 和域名配置完成。
4. 没有任何用户图片持久化路径。
5. 隐私政策与产品实际数据流一致。
6. 至少使用 30 张普通商品图完成上线前测试，并记录成功率。
7. 已准备用户招募渠道、反馈入口和 7 天验证指标记录方式。

## 14. 进入第二阶段的条件

只有达到第 2 节的核心验证指标后，才讨论第二阶段功能。优先候选包括：

- 付费图片包或订阅。
- Shopify 导入和写回。
- 更多平台尺寸与合规检查。
- 更稳定的批量任务和历史记录。
- 人工精修或复杂边缘增强。

如果真实上传少于 5 位用户、无人愿意支付 USD 5，或普通商品图可接受率低于 70%，则停止扩展功能，先重新验证目标用户或价值主张。
